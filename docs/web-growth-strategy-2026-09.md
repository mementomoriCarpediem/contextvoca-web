# contextvoca.app 웹 노출 개선 전략 (2026-09-10)

정본. 근거는 2026-09-10 실측(사이트 구조·색인·로그)과 researcher 조사(검색 35회, 1차 출처 위주)이며, 검색량은 로그인 도구 접근 불가로 전부 미측정이다. 추정 수치는 넣지 않았다.

## 1. 진단 — 왜 노출이 0에 가까운가

| 항목 | 실측 |
|---|---|
| 페이지 구성 | 5개 언어 × 4페이지(홈·지원·개인정보·약관) = 20 URL. 검색어를 겨냥한 콘텐츠 페이지 0 |
| 색인 | 구글 KR/JP/US·네이버 색인됨. Bing·DuckDuckGo 미색인(Bingbot 방문 0 → ChatGPT 검색 대상 아님) |
| 유입 | 9/3 로그 8일: 사람 방문 0(페이지뷰 대부분 스캐너). 이후 변화 신호 없음 |
| 기반 작업 | 8/28~9/7: 검색엔진 등록, 메타·hreflang 정합, 번체 페이지, 스토어 링크 계측(/go/), llms.txt, IndexNow. 전부 "받을 준비"만 됐고 "검색될 이유"가 없음 |
| 보유 자산 | 과학 근거 문안 정본(연구 10건, 1차 출처 대조 완료, `docs/science-claims.md`), 스토어 등록정보 5개 언어, note 게시글 1편(9/9) |

결론: 브랜드명을 모르는 사람이 검색으로 도달할 경로가 구조적으로 없다. 메타 최적화로는 해결되지 않고, **검색 의도에 답하는 콘텐츠 페이지**가 유일한 근본 해법이다.

## 2. 조사로 확인된 사실 (1차 출처)

- **같은 유형의 앱이 콘텐츠로 유입을 만들고 있다.** KaChiKa(사진 어휘 앱, kachika.app)는 한국어 블로그 12편(JLPT 급수별·토익·에빙하우스·Anki 대안·사진→단어장)으로, 네이버 통합검색 "영어단어장 앱 추천"·"토익 단어 외우는 법 직장인"의 **AI 브리핑 인용 출처**가 되고, "사진 단어장 만들기 앱"에서는 웹사이트 탭에 자체 블로그가 직접 노출된다(2026-09-10 네이버 결과 HTML 직접 파싱, zorba 재대조). 도메인 첫 기록 2025-01 → 약 20개월 만의 결과.
- **일본**: TANZAM(이미지+예문 영단어 앱)이 英検 급수별(5級~1級)·TOEIC 목표 점수별·IELTS Band별 컬럼 다수로 세분 롱테일을 점유(tanzam.net/column 직접 확인).
- **대만**: 英文庫(english.cool)가 시험 급수별 700여 편으로 영어 학습 블로그 트래픽 상위권(2차 출처). 넓은 "앱 추천" 라운드업은 어필리에이트 블로그와 Dcard·PTT가 장악.
- **경쟁 약한 축**: "사진/카메라로 단어장 만들기"(KR), "写真 単語帳 作成"(JP), "拍照背單字"(TW)는 앱 스토어 페이지와 2015년 기사만 있고 최신 콘텐츠는 미발견(공백 단정 아님).
- **한국의 네이버 특수성**: 자체 도메인은 네이버 통합검색의 웹사이트 탭과 AI 브리핑 인용으로 노출된다. 블로그 탭은 네이버 블로그 전용.
- **신규 도메인 반박**: "써도 안 뜬다"는 KaChiKa 사례로 반박되나 표본 1이며 시간축은 수주~수개월 뒤 롱테일부터. 확신도 중간.

**2026-09-19 개정**(대표님 "진행"): 언어 로케일 ≠ 시험 권역. 로케일별 시험·형식·응시 규모의 정본은 `docs/exam-map-by-locale-2026-09.md`(시행 기관 원문 대조). 아래 표는 그 지도를 반영한 것이며, 미확인 항목은 지도에 남겨 두었다.

첫 4주는 한국어에 집중(A 2편 + B 5편 + C 1편 순), 5주차부터 일본어를 병행한다. 콘텐츠는 콘텐츠 파이프라인(기획 → 제작 → 검수 → 대표님 승인 → 발행)을 따르고 자동 게시는 하지 않는다.

## 6. 기술 기반 (콘텐츠 시작 전 1주)

1. **블로그 인프라**: Next.js 정적 사이트에 MDX 블로그 라우트(`/{locale}/blog/[slug]`), 목록·태그, Article JSON-LD, hreflang, 자동 sitemap, 발행 시 IndexNow 제출 스크립트.
2. **Bing Webmaster 등록**(대표님 1분, GSC 가져오기) — ChatGPT 검색 노출의 전제.
3. **Search Console API 활성화**(GCP 프로젝트 `contextvoca`에서 API 켜기 + 서비스 계정을 GSC 속성 사용자로 추가) — 주간 노출·클릭·검색어를 자동 보고에 포함.
4. **검색량 실측 도구**: 네이버 검색광고 키워드도구·Google Keyword Planner 접근이 있어야 우선순위를 수치로 정한다. 없으면 상대 우선순위(경쟁 약함 → 실증 템플릿 순)로 진행.
5. `llms.txt`·`/go/` 계측은 이미 있음. 블로그 글의 스토어 CTA는 전부 `/go/` 경유로 통일.

## 7. 측정과 판정 기준

기준선(2026-09-10): 사람 유입 0, 노출 미측정, 스토어 클릭(/go/) 미집계 상태.

주간 지표(기존 주간 보고에 추가): GSC 노출·클릭·상위 검색어(API 활성화 후), 네이버 서치어드바이저 노출, /go/ 클릭, RevenueCat 국가별 신규 고객.

판정: 콘텐츠 축적 8주 시점에 "어느 롱테일 검색어에서든 20위 이내 진입"과 "월 스토어 클릭 발생"을 확인한다. 둘 다 없으면 축 B의 키워드 선정 방식을 재검토하고, 있으면 그 축에 집중 배분한다. 절대 수치 목표는 검색량 실측 후에 정한다.

## 8. 리스크

- **신규 도메인 지연**: 성과는 수주~수개월 후 롱테일부터. 4주 만에 판단하지 않는다.
- **근거 없는 주장**: 효과 수치·"과학적으로 증명" 표현 금지. 정본 밖 주장은 검수에서 반려.
- **기밀 경계**: 콘텐츠에 내부 시스템·미발행 기획·개인 신원 노출 금지(전역 규칙).
- **네이버 블로그 운영 부담**: 별도 계정·수동 게시가 필요. 운영 여부를 먼저 결정.
- **비교 콘텐츠 분쟁**: 타사 기능 서술은 공개 정보 범위, 비하 표현 금지.

## 9. 대표님 결정 필요

1. 네이버 블로그 계정을 운영할지(운영 시 발행은 대표님 수동).
2. 검색량 도구(네이버 검색광고·Keyword Planner) 계정 접근 제공 여부.
3. Bing Webmaster 등록·GSC API 활성화(각 몇 분, 대표님 계정).
4. 첫 8주 콘텐츠 승인 방식 — 편별 승인(현행 SOP) 또는 주간 묶음 승인.

착수 지시 시 순서: 6절 기술 기반(1주) → 한국어 축 A·B 첫 4편 기획서 → 검수 → 승인 → 발행.
